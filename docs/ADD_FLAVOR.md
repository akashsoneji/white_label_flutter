# Add a New Flavor (Brand) — One-Command Workflow

> **Quick start:** one script writes **12+ files across Android, iOS, Flutter
> Dart, and VSCode** for a new brand. Read this doc end-to-end the first time,
> then jump straight to the [Quickstart](#quickstart) for every new flavor.

---

## Quickstart

```bash
dart run scripts/add_flavor.dart \
  --name <brand_id> \
  --type child \
  --parent vantage \
  --label "Display Name" \
  --primary "#RRGGBB" \
  --secondary "#RRGGBB" \
  --accent "#RRGGBB" \
  --api "https://api.<brand>/api/" \
  --websocket "wss://api.<brand>/trade-engine" \
  --chart "https://api.<brand>"
```

After the script finishes, the brand is **fully buildable**:

- **VSCode** → open Run & Debug panel → pick `<brand> (debug)` → press **F5**
- **CLI** → `flutter run --flavor <brand> --dart-define=CLIENT=<brand> --dart-define=FLAVOR=<brand>`

To customize the icon, drop a 1024×1024 PNG at `assets/brands/<brand>/icon.png`
and re-run `dart run scripts/prepare_flavor.dart <brand>`.

## Examples

### Vantage child (4-tab UI tree, shared with Vantage/Pipze/Tenax/Baazex/etc.)

```bash
dart run scripts/add_flavor.dart \
  --name acme --type child --parent vantage \
  --label "Acme Trading" \
  --primary "#1B5E20" --secondary "#A5D6A7" --accent "#FFB300" \
  --api "https://api.acme.io/api/" \
  --websocket "wss://api.acme.io/trade-engine" \
  --chart "https://api.acme.io"
```

### Celestial child (5-tab standalone UI tree)

```bash
dart run scripts/add_flavor.dart \
  --name alpha --type child --parent celestial \
  --label "Alpha Markets" \
  --primary "#0D47A1" --secondary "#E3F2FD" --accent "#FFB300" \
  --api "https://api.alpha.io/api/" \
  --websocket "wss://api.alpha.io/trade-engine" \
  --chart "https://api.alpha.io"
```

### Standalone parent (own UI tree — must add screens under `lib/screens/*/brands/<name>/` later)

```bash
dart run scripts/add_flavor.dart \
  --name stellar --type parent \
  --label "Stellar Markets" \
  --primary "#0D47A1" --secondary "#E3F2FD" --accent "#FFB300" \
  --api "https://api.stellar.io/api/" \
  --websocket "wss://api.stellar.io/trade-engine" \
  --chart "https://api.stellar.io"
```

### Dry run (verify the plan without writing anything)

```bash
dart run scripts/add_flavor.dart \
  --name acme --type child --parent vantage \
  --primary "#1B5E20" --api "https://api.acme.io/api/" \
  --websocket "wss://api.acme.io/trade-engine" --chart "https://api.acme.io" \
  --dry-run
```

## All flags

| Flag | Required | Default | Notes |
|---|---|---|---|
| `--name` | ✅ | — | Lowercase ID, e.g. `acme`. Reserved names blocked: `android`, `ios`, `main`, `debug`, `profile`, `test`. |
| `--type` | ✅ | — | `parent` (own UI tree) or `child` (inherits parent screens). |
| `--parent` | required if `--type=child` | — | Existing parent id. Currently `vantage`, `celestial`. |
| `--label` | — | `--name` | Display label (e.g. `"Acme Trading"`). |
| `--primary` | ✅ | — | `#RRGGBB`. Required. |
| `--secondary` | — | `#FFFFFF` | `#RRGGBB`. |
| `--accent` | — | `--primary` | `#RRGGBB`. |
| `--splashColor` | — | `--primary` | Android splash background. |
| `--launcherBackground` | — | `--primary` | Android adaptive icon background. |
| `--api` | ✅ | — | Full API base URL (trailing `/` auto-added). |
| `--websocket` | ✅ | — | WebSocket URL. |
| `--chart` | ✅ | — | Chart base URL. |
| `--applicationId` | — | `com.<name>.app` | Android applicationId / iOS bundleId. |
| `--appName` | — | `--label` | Display name on launcher. |
| `--iconPath` | — | parent's icon.png | Override source icon (PNG). |
| `--themeMode` | — | `both` | `light` \| `dark` \| `both`. |
| `--dry-run` | — | — | Print plan, write nothing. |
| `--help`, `-h` | — | — | Show full help. |

## What the script does

The script writes **12 places** in one shot, then calls
`scripts/generate_brand_config.dart` to fill in everything the generator owns.

### Files this script writes directly (1-6)

1. **`assets/brands/<name>/brand.yaml`** — Full YAML (name, type, parent,
   label, colors, URLs, assets, features).
2. **`assets/brands/<name>/icon.png`** — Copied from `--iconPath` or parent's
   icon.png. Replace with the real 1024×1024 logo before shipping.
3. **`assets/brands/<name>/logo.svg`** + **`splash_logo.svg`** — Copied from
   parent. Replace with brand-specific SVGs.
4. **`android/app/src/<name>/AndroidManifest.xml`** — Standard Flutter
   manifest template (permissions, FileProvider, MainActivity).
5. **`android/app/src/<name>/res/xml/file_paths.xml`** — FileProvider paths.
6. **`lib/app/ui_registry.dart` → `_uiParentByClient` map** — Inserts
   `'<name>': '<parent>'` so runtime resolves the right UI tree. **This is
   the one place the generator doesn't touch**, which is why `add_flavor.dart`
   patches it manually.

### Files generated by `generate_brand_config.dart` (invoked at the end)

7. **`lib/clients/<name>/config.dart`** — `<Name>Config extends BaseClientConfig`
   with primary/dark/secondary/accent colors, API URLs, asset paths.
8. **`lib/clients/<name>/launcher_icons.yaml`** — flutter_launcher_icons config
   (Android + iOS, adaptive icon background color).
9. **`lib/flavor_config.dart`** — Adds `<name>` to `Flavor` enum, switch case
   in `_configFor()`, `is<Name>()` getter, and to the `usesVantageUi()` set
   if parent is `vantage`.
10. **`assets/config/brands/brands.yaml`** + **`brands.json`** — Adds the
    brand to the central registry.
11. **`android/brand_flavors.gradle`** — Adds the flavor block with all
    `resValue("color", ...)` entries + `appId` / `appName` / `type` /
    `inheritsFrom`.
12. **`.vscode/launch.json`** + **`.vscode/tasks.json`** — Adds 3 launch
    configurations (`<name> (debug/profile/release)`) + a `prepare-<name>`
    preLaunchTask that calls `prepare_flavor.dart <name>` so VSCode-direct
    F5 runs regenerate icons/splash/colors automatically.

### After the script runs

VSCode will pick up the new launch config after a window reload
(⇧⌘P → "Developer: Reload Window"). The new brand's dropdown entries appear
in the Run & Debug panel:

```
🟢 <Display Name> (debug)    ← F5 here for development
🟡 <Display Name> (profile)  ← for profiling
🔵 <Display Name> (release)  ← for release-mode testing
```

## Architecture: parent vs child brands

```
                          ┌─────────────────┐
                          │    vantage      │  ← type: parent (4-tab UI tree)
                          │  lib/screens/…/ │
                          │  brands/vantage │
                          └────────┬────────┘
                                   │ inheritsFrom: vantage
              ┌────────────────────┼────────────────────┐
              │                    │                    │
        ┌─────▼─────┐        ┌─────▼─────┐        ┌─────▼─────┐
        │  pipze    │        │  baazex   │  …     │  skyriss  │
        └───────────┘        └───────────┘        └───────────┘
        (all share vantage's screen files at runtime)
```

```
                          ┌─────────────────┐
                          │   celestial     │  ← type: parent (5-tab UI tree)
                          │ lib/brands/     │
                          │  celestial/     │
                          └────────┬────────┘
                                   │ inheritsFrom: celestial
                            ┌──────▼──────┐
                            │   <child>   │
                            └─────────────┘
```

| Layer | What decides parent/child routing |
|---|---|
| `lib/app/ui_registry.dart` | `_uiParentByClient[<brand>]` → maps to `vantage` or `celestial` (or any future parent). |
| `lib/flavor_config.dart` | `usesVantageUi()` set — includes every Vantage child so 15 widget branches gate correctly. |
| `prepare_flavor.dart` | `loadInheritance(<brand>)` walks the parent chain so assets/clients/<parent>/ stays bundled for child APKs. |
| `android/brand_flavors.gradle` | `type: child, inheritsFrom: vantage` so Android Gradle resolves the same tree. |

When you add a **new Vantage child**, the script handles all four layers
automatically. **Celestial children** need `parent: celestial` and the
`CelestialMainShell` already supports them.

## Validation rules (script fails fast on these)

| Rule | Example violation |
|---|---|
| `--name` must be `^[a-z][a-z0-9_]{0,30}$` | `--name "Acme"` ❌ (uppercase) |
| `--type` must be `parent` or `child` | `--type sibling` ❌ |
| `--type=child` requires `--parent` | missing flag ❌ |
| Parent must exist (case-insensitive) | `--parent foo` if `foo/` doesn't have `brand.yaml` ❌ |
| `--type=parent` rejects `--parent` | redundant flag ❌ |
| Hex colors must be `#RRGGBB` (or `#AARRGGBB`) | `--primary "#GGGGGG"` ❌ |
| Reserved names blocked | `--name android` ❌ |
| Duplicate brand check | re-running for an existing brand ❌ |

## Build matrix after adding a brand

| Action | Command |
|---|---|
| Add a brand | `dart run scripts/add_flavor.dart --name ... --type ... --parent ... …` |
| Update icon (after replacing `icon.png`) | `dart run scripts/prepare_flavor.dart <name>` |
| Re-run from VSCode | Reload window, pick `<name> (debug)`, press F5 |
| Run on iOS sim | `flutter run --flavor <name> -d <device>` |
| Build release APK | `flutter build apk --release --flavor <name> --dart-define=CLIENT=<name> --dart-define=FLAVOR=<name>` |
| Build release IPA | `flutter build ipa --release --flavor <name> --dart-define=CLIENT=<name> --dart-define=FLAVOR=<name>` |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| "Brand already exists" | You ran the script twice for the same id | Delete `assets/brands/<name>/` first, or pick a different name |
| "Parent does not exist" | `--type=child --parent=foo` but `foo/` has no `brand.yaml` | Check existing parents via `ls assets/brands/` |
| "Invalid hex color" | Used `#XYZ` or `0x123456` shorthand | Use 6-digit `#RRGGBB` |
| Build icon shows old logo | `prepare_flavor.dart` not run after replacing icon | `dart run scripts/prepare_flavor.dart <name>` |
| VSCode dropdown doesn't show new brand | Window not reloaded | ⇧⌘P → "Developer: Reload Window" |
| Brand shows wrong color in app | `flavor_config.dart` enum/switch not updated | `dart run scripts/generate_brand_config.dart` |
| Build error: `Could not find _uiParentByClient` | `lib/app/ui_registry.dart` was hand-edited away from default | Re-run `add_flavor.dart` to patch it back |

## Files this doc references

| File | Role |
|---|---|
| `scripts/add_flavor.dart` | The one-shot scaffolder. |
| `scripts/generate_brand_config.dart` | Generates Dart/Gradle/launch.json/tasks.json from brand.yaml. |
| `scripts/prepare_flavor.dart` | Build-time: copies assets, generates icons/splash/pubspec for the active flavor. |
| `assets/brands/<name>/brand.yaml` | Source of truth for each brand. |
| `lib/clients/<name>/config.dart` | Auto-generated runtime config (colors, URLs). |
| `lib/flavor_config.dart` | Auto-generated Flavor enum + per-flavor config switch. |
| `lib/app/ui_registry.dart` | Hand-patched by `add_flavor.dart` (only thing the generator doesn't touch). |
| `android/brand_flavors.gradle` | Auto-generated Gradle flavor list. |
| `.vscode/launch.json` | Auto-generated VSCode debug configurations. |
| `.vscode/tasks.json` | Auto-generated `prepare-<brand>` tasks. |

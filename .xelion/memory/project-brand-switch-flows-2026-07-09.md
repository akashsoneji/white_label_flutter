Brand switching flows (./build.sh + VS Code launch.json) on 2026-07-09:

**Build-time brand selection (./build.sh):**
- `./build.sh <brand> apk release` runs `prepare_flavor.dart <brand>` (regenerates client assets, swaps `assets/clients/`, rebuilds splash/icons), then runs `flutter build apk --flavor <brand> --dart-define=CLIENT=<brand> --dart-define=FLAVOR=<brand>`. Verified working for pipze (build/app/outputs/flutter-apk/PIPZE_V1.0.119_release_*.apk produced), celestial, and meta. The URL and flavor correctly change.

**VS Code debug (launch.json F5):**
- Each brand has 3 entries (debug/profile/release) in `.vscode/launch.json`. Each entry has `args: ["--flavor", "<brand>", "--dart-define=CLIENT=<brand>", "--dart-define=FLAVOR=<brand>", ...]` and `preLaunchTask: "prepare-<brand>"`. Pressing F5 with e.g. "🟡 Celestial (debug)" selected runs `prepare-celestial` → swaps assets → launches Flutter with `--dart-define=CLIENT=celestial` baked in.

**How main.dart picks the brand:**
- `lib/main.dart:_initializeFlavor()` (top-level Future) reads `String.fromEnvironment('CLIENT', defaultValue: '')` first, then falls back to `String.fromEnvironment('FLAVOR')`, then calls `FlavorConfig.activateByName(selected)`. The activated flavor's `apiBaseUrl`, `websocketUrl`, `primaryColor`, etc. come from the per-client config (`lib/clients/<brand>/config.dart`) which is itself generated from `assets/brands/<brand>/brand.yaml`.

**Why: **`./build.sh <brand>` ↔ F5 with `<brand>` config both end up calling `_initializeFlavor()` with the same `--dart-define=CLIENT=<brand>`. No manual switching needed — the build command and the debug config are kept in lock-step by `prepare_flavor.dart` regenerating both `lib/clients/<brand>/config.dart` and `.vscode/launch.json` simultaneously.

**How to apply:**
- When adding a new brand, ensure the new `Flavor` enum entry + per-client config + `brand.yaml` are all generated by `scripts/generate_brand_config.dart` — the same generator also writes launch.json + tasks.json entries, so the F5 debug flow stays in sync automatically.
- All 10 brand configs live in `lib/clients/<brand>/config.dart` (PipzeConfig, CelestialConfig, MetaConfig, VantageConfig, …). The active brand at runtime is whichever was passed via `--dart-define=CLIENT=` (or fall back to `--dart-define=FLAVOR=`); missing/empty means `Flavor.vantage` (default).
- In-app brand switching (via the dev-only `BrandSwitcher` widget) also works: it calls `FlavorConfig.activateByName(name)` directly. UI re-renders automatically via `UiRegistry.tradingMain()` + `BrandResolver.activeBrand` → all consumers watch the Obx.

**Files:**
- `lib/main.dart` — `_initializeFlavor()` reads `String.fromEnvironment('CLIENT')` / `'FLAVOR'` and activates.
- `lib/flavor_config.dart` — generated. Has `activateByName(String)` and `applyBranding(...)` runtime helpers.
- `lib/app/ui_registry.dart` — picks the right shell per brand (`MetaMainShell` / `CelestialMainShell` / `TradingMainScreen`).
- `lib/brands/brand_resolver.dart` — wraps active brand state.
- `.vscode/launch.json` — 30 entries (10 brands × 3 modes), each passes the right `--dart-define`.
- `.vscode/tasks.json` — `prepare-<brand>` tasks call `prepare_flavor.dart <brand>`.
- `build.sh` — shell entry: `./build.sh <brand> <target> <mode>` → `prepare_flavor.dart` + `flutter build`.
- `scripts/prepare_flavor.dart` — swaps client assets in `assets/clients/`, regenerates iOS Brand.xcconfig / Android splash.
